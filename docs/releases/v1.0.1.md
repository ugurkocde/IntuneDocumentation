# v1.0.1: browser session security and expanded compliance evidence

## Security and retention

The hosted public site remains at https://intunedocumentation.com. Microsoft sign-in and the dashboard move to https://app.intunedocumentation.com. Crisp support chat and Plausible analytics run only on the public origin, keeping those scripts outside the browser origin containing authentication and tenant snapshots. Public pages clear legacy session storage before loading public scripts. Existing users must sign in again on the app origin.

App pages use a fresh script nonce on each HTML response. Production script policies no longer allow unrestricted inline JavaScript or eval. HTML is dynamically rendered and must not be cached by a CDN. Inline styles remain allowed for the UI.

Dashboard snapshots expire one hour after the original collection time. Expiry removes the stored snapshot while leaving an already open report usable. Restoration and tab-resume checks reject expired data, including data retained by browser session restoration. Sign-out clears the current tab and sends only a logout signal to other open app tabs, which clear their snapshots and local authentication. Cross-tab messaging requires browser BroadcastChannel support. This snapshot limit does not change Microsoft token lifetimes.

## Reliability and user experience

Browser reloads restore a compressed snapshot from the tab's sessionStorage after authentication settles, avoiding another full Graph collection while the snapshot is valid. Snapshots are scoped to the account, tenant, and collection options. Refresh data explicitly starts a collection; the dashboard recommends refreshing after 30 minutes. Failed refreshes preserve previously loaded data and its timestamp.

If browser storage is full or blocked, the current dashboard continues working without a storage warning. A later reload collects data again. There is no server, localStorage, or IndexedDB fallback for tenant snapshots, and generated reports remain in the browser.

Collection warnings now distinguish missing API responses from confirmed empty collections and explain the impact on exports. Permission hints no longer imply that a missing response proves insufficient permissions. The retired Windows Information Protection without-enrollment endpoint is no longer collected. Script assignments, compliance scheduled actions, configuration values, report pagination, and Conditional Access reporting also received fixes since v1.0.0.

## Compliance evidence

The dashboard now includes technical evidence assessment and downloadable reports for mapped framework requirements, including Essential Eight maturity targets, ISO/IEC 27001:2022, SOC 2, Def Stan 05-138, Cyber Essentials, and NIST SP 800-171 revisions 2 and 3. Available supported technical checks are evaluated, and missing sources or unsupported detection are explained. Group display names make assignment evidence easier to review.

These assessments cover the application's mapped technical checks. They do not certify full framework compliance, verify effective device state, or replace organizational evidence and an audit.

## Upgrade and self-hosting notes

For a split public/app deployment, configure both server environment variables:

```env
PUBLIC_SITE_ORIGIN=https://intunedocumentation.com
APP_SITE_ORIGIN=https://app.intunedocumentation.com
```

Use your own distinct origins when self-hosting. Map both hosts to the deployment and add the app origin as a **Single-page application** redirect URI in the Entra app registration before enabling the variables. Preserve any other redirect URIs still needed by existing installations. Public dashboard requests redirect to the app, and public-origin Intune collection endpoints are unavailable.

Leave both variables unset for a single-origin private installation. Chat and analytics are disabled there, including on the landing page. To retain public scripts, configure a separate public origin and the existing script settings. Setting only one origin or using the same origin for both is invalid.

Old snapshot formats are discarded on upgrade and collected again. Multi-architecture container images are published for linux/amd64 and linux/arm64.
